$ jod --help
Delegate to an agent harness and watch it work.

Usage: jod <COMMAND>

Commands:

  ls         List the agents this process knows about

  watch      Follow a running agent, or replay a finished one

  report     Counts and total spend across all agents

  remember   Teach Jod something it should remember
  recall     Search what Jod remembers
  forget     Permanently destroy a fact — every version of it, not just the current
  tui        The full-screen interface: conversation, live agents, status
  team       Agent teams: several agents on one job, talking to each other
  daemon     Run the scheduler: fire due schedules and advance goals, for ever
  conv       Conversations Jod owns: list them, fork one, take one back
  schedule   Work that fires on the clock
  goal       Standing objectives, pursued until they are met
  related    What Jod's memory connects to a thing
  path       How two things in memory are connected, if they are
  chat       Hold a conversation on a plain terminal, without the full-screen UI
  help       Print this message or the help of the given subcommand(s)

Options:
  -h, --help     Print help
  -V, --version  Print version

== jod remember

$ jod remember --help
Teach Jod something it should remember

Usage: jod remember [OPTIONS] <SUBJECT> <PREDICATE> <OBJECT>

Arguments:
  <SUBJECT>
          What the fact is about, e.g. "reljod"

  <PREDICATE>
          The relation, e.g. "prefers"

  <OBJECT>
          The value, e.g. "linear for tasks"

Options:
      --source <SOURCE>
          Where this came from — a note path, a URL, a person

      --scope <SCOPE>
          Which domain this belongs to. Scopes are hard partitions
          
          [default: default]

      --origin <ORIGIN>
          Who asserted it. Never inferred from the text itself

          Possible values:
          - owner:     Reljod said so. The default when a human types `jod remember`
          - agent:     An agent concluded it
          - untrusted: Read from outside — a page, an email, a document
          - system:    Jod itself recorded it
          
          [default: owner]

  -h, --help
          Print help (see a summary with '-h')

== jod conv
==============================================================
$ jod conv --help
Conversations Jod owns: list them, fork one, take one back.

A conversation here is a tree, not a line. Two of the three harnesses can fork themselves and none can hand a thread to another, so the transcript that survives a harness switch has to be Jod's.

Usage: jod conv <COMMAND>

Commands:
  ls       Every conversation, newest first
  show     Read one, from its root to wherever its head currently points
  fork     Copy a conversation from a point, leaving the original untouched
  revert   Move the head back to an earlier message
  goto     Point the head at any message sharing this conversation's root — including a branch abandoned earlier, which revert cannot reach because it is a cousin of the head rather than an ancestor
  search   Search every conversation. Returns the match with the conversation's opening and closing around it, so a hit reads without the transcript
  compact  Summarise a span out of the live window, keeping it on disk
  handoff  What this conversation would be handed to another harness as
  help     Print this message or the help of the given subcommand(s)

Options:
  -h, --help
          Print help (see a summary with '-h')

== jod schedule
==============================================================
$ jod schedule --help
Work that fires on the clock.

A schedule is a prompt, a cron expression and a timezone. Everything else — what to do about a run that overran, or instants missed while Jod was down — is policy with a default that was chosen by measuring what happens without it.

Usage: jod schedule <COMMAND>

Commands:
  ls      Every schedule, with when it next fires
  add     Arm a new one
  pause   Stop a schedule firing, without forgetting it
  resume  Arm it again. Also clears whatever failure count stopped it
  run     Fire it now, through the ordinary tick so every policy still applies
  rm      Forget a schedule and its history
  log     What a schedule has done lately
  help    Print this message or the help of the given subcommand(s)

Options:
  -h, --help
          Print help (see a summary with '-h')

== jod goal
==============================================================
$ jod goal --help
Standing objectives, pursued until they are met.

A goal differs from a schedule in having an end: it stops when it is satisfied, when it runs out of budget or iterations, or when it stops making progress. That last one matters most — a loop that keeps running while nothing changes looks exactly like a loop doing useful work.

Usage: jod goal <COMMAND>

Commands:
  ls      
  add     Set a standing objective
  pause   
  resume  
  run     Run one iteration now
  rm      
  log     What this goal has done, out of its own memory
  help    Print this message or the help of the given subcommand(s)

Options:
  -h, --help
          Print help (see a summary with '-h')

== jod daemon
==============================================================
$ jod daemon --help
Run the scheduler: fire due schedules and advance goals, for ever.

This is the process that makes a schedule mean anything. Without it the tick exists and is tested and nothing calls it, so `jod schedule ls` describes work that will never happen. Install it with `deploy/jod-daemon.service`.

Usage: jod daemon [OPTIONS]

Options:
      --once
          Tick once and exit, rather than staying resident. For a systemd timer, or for checking the thing works before enabling the unit

  -h, --help
          Print help (see a summary with '-h')

== jod team
==============================================================
$ jod team --help
Agent teams: several agents on one job, talking to each other.

A team can mix harnesses — a lead on Claude Code with teammates on AGY and OpenCode — which is the thing no single harness can do.

Usage: jod team <COMMAND>

Commands:
  join   Put a member on a team, or update the one already there
  task   Put a task on the team's board
  claim  Take ownership of a task. Reports whether this member won the race
  done   Mark a task finished
  msg    Send a message. Without --to it goes to every member but the sender
  inbox  Read a member's waiting messages and mark them delivered
  wake   Deliver waiting messages: resume every idle member that has mail
  start  Give a member its first turn, so it has a conversation to resume
  show   Who is on the team, and what is on its board
  list   Every team that has a member
  help   Print this message or the help of the given subcommand(s)

Options:
  -h, --help
          Print help (see a summary with '-h')

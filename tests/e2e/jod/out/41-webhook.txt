== 11. does restarting the daemon make a revoked token stop working?
==============================================================
$ jod-api token issue tempdevice --scope read
jod_f34b4da15eca39c255dfb1e29dc9eb40f24e85ff164b579ec262cfd020c6378d

Label: tempdevice
Scope: read
Stored (hashed) in /tmp/jod-e2e/webhook/api-tokens.json

This is the only time the token is shown. Store it in the
device's keychain, not in a file or a shell history.

$ curl -sS -o /dev/null -w 'before revoke: HTTP %{http_code}\n' -H 'Authorization: Bearer jod_605efe93040c2c81d9eab026df8b7c4373dea063a8f216b6084cf82810d9591e' 'http://127.0.0.1:18788/v1/agents'
before revoke: HTTP 401

$ jod-api token revoke tempdevice2
revoked 1 token(s) labelled tempdevice2

$ curl -sS -o /dev/null -w 'after revoke, same daemon: HTTP %{http_code}\n' -H 'Authorization: Bearer jod_605efe93040c2c81d9eab026df8b7c4373dea063a8f216b6084cf82810d9591e' 'http://127.0.0.1:18788/v1/agents'
after revoke, same daemon: HTTP 401

$ curl -sS -o /dev/null -w 'after revoke, restarted daemon: HTTP %{http_code}\n' -H 'Authorization: Bearer jod_605efe93040c2c81d9eab026df8b7c4373dea063a8f216b6084cf82810d9591e' 'http://127.0.0.1:18788/v1/agents'
after revoke, restarted daemon: HTTP 401

daemon stopped

The Delegation Crossover

One agent that manages its own context and hands work to others is the dominant 2026 pattern. It is also, most of the time, a way to spend four to thirty-five times more for exactly the same answer. This is where the line actually falls.

The pattern is called orchestrator–worker. It works — but only above one line. Delegate when the task cannot be narrowed by search before reading, and not otherwise. Below that line it costs 4–35× for no accuracy at all.

Everything below is scored against generated ground truth, so no model graded the agents. Where a number rests on few trials, the n is given.

The contradiction this had to settle

The published record disagrees with itself, and both sides are credible.

Anthropic reports a multi-agent research system beating a single agent by 90.2%, at roughly fifteen times the tokens. Cognition published “Don’t Build Multi-Agents,” arguing that dispersed decisions and incomplete context sharing make such systems fragile, and that context engineering matters more.

Both are right. They sit on opposite sides of a crossover nobody had located precisely. Locating it was the point of the experiment — and the answer is not the one usually given.

Where the line actually falls

A single agent and a four-worker fan-out ran the same tasks over generated corpora with known answers. The tasks differ in shape, not just size.

The fourth row is the important one. A corpus five times larger than the context window caused no trouble at all — the agent searched instead of reading, scored a perfect 1.000, and beat fan-out by thirty-five times on cost. Only when the criteria were paraphrased so that search could not find them, forcing every file to be read, did the single agent collapse.

The trigger is not “my data is bigger than the context window.” Search makes most large corpora fit. The trigger is that the work itself cannot be narrowed before reading.

The five that matter

Ranked by how much the system degrades without them. The numbering is a real ordering, and it is not the ranking this study started with — two entries changed once the evidence arrived.

1

Gate delegation on task shape, not corpus size

measured

Delegate only when the task cannot be narrowed by search before reading. Below that line delegation is strictly dominated: identical accuracy at 4× cost on breadth tasks, and 7.4× cost with 6× latency on a sequential task, where there is nothing to parallelise because each step’s input is the previous step’s output.

2

Make every worker return say what it is

measured

The largest effect found anywhere in this study, and the cheapest to apply.

Worker returnScoreCost
Bare answer0.000  (4/4 failed)$0.18
+ one clause of self-description0.978$0.23
Full reasoning, then answer1.000$0.27

Found by accident. Fan-out scored zero on a task where the workers were demonstrably right — between them they found every target file. The merging agent threw their work away and asked for reports it had already been given, because on that task the answer type (file paths) matched the input type (file paths). A bare answer was indistinguishable from the worker’s own assignment.

The fix is not verbosity. Full reasoning works because it is self-evidently a set of findings; one clause achieves the same thing at a fifth of the extra cost.

3

Isolation is the mechanism; worker count is the cost dial

measured

The value of a sub-agent is that it burns its own context and returns a summary — not that it runs in parallel. But every worker starts a fresh prefix and pays for it.

Cache creation is 20× higher at eight workers. Delegation and prompt-cache efficiency pull directly against each other, which is rarely said out loud. Watch the ratio of tokens a worker burns to tokens it returns: near 1 means the isolation is doing nothing and you are paying for a round trip.

4

Verify by a different method, not a second opinion

measured

Every configuration got one task wrong, and wrong identically: asked to sum only one category, agents returned the sum of all four. Fifteen runs across five configurations produced zero catches.

The critic re-reads the task and misreads it the same way, because the error is in how the task is read, not in the arithmetic. Only a check by a genuinely different method — an assertion, a recomputation by another route, ground truth — catches this class of error.

Verification also has a headroom condition. On a task already scoring 0.986, adding a critic lowered it to 0.752. A critic that cannot improve a correct answer can only damage it.

5

Durable execution with an inbox

not measured here

Persist the run so it can resume, and put a queue in front of it so a human can interrupt or redirect without losing work. This is the one entry in the five that this study did not test. It is included on two other grounds: an independent panel of five model families put durable execution on 15 of 15 ballots with the most first-place votes, and the agent inbox topped the tally outright. And it follows from the requirement — once a task outlives a process, resumability is the difference between a system and a demonstration.

It is labelled separately because it is not a result.

Five things I expected that were wrong

The refuted hypotheses were more useful than the confirmed ones.

Hypothesis 8

Agents over-delegate when offered the option.

They declined. spawned: 0 on every task that fit in context. Recording the spawn count is what made this falsifiable — without it, “delegation allowed” and “delegation used” are indistinguishable.

Hypothesis 15

Terse worker returns beat verbose ones.

The opposite, decisively: 0.000 against 1.000. Size was the wrong variable. Ambiguity was the right one.

Hypothesis 33

A clean-context critic beats a shared-context one.

It measured worse (0.752 against 0.970). Lacking the original reasoning, it re-derives from scratch and sometimes overwrites a correct answer.

Hypothesis 40

A second look beats a second agent.

Neither worked. When author and critic share a blind spot, both are blind. Only an independent method catches it.

Hypothesis 13

A rich worker brief beats a vague one.

No measurable difference — both scored 1.000 on the unambiguous task. The dominant failure was somewhere else entirely.

Hypothesis 27

Reciting the objective prevents drift.

Adherence was 1.000 in every condition at 122k tokens. Drift never appeared. What degraded was recall — a different problem.

Can you trust an LLM to grade this?

Mostly not — which is why this study generated its own ground truth.

Because every answer already had an objective score, the judges could be measured rather than trusted. Five conditions crossed model family, rubric style, and whether the judge could read the source.

No condition exceeded 0.67. Judges separate good from bad on average — 72.1 on perfect answers against 25.4 on worthless ones — but the tail is what bites: 29% of objectively worthless answers scored above 50, and 21% scored above 70.

The clearest case was an answer that emitted the literal template CODE=84,CODE=134,… containing no real data whatsoever. True score 0.00. All five judges rated it 68–90 — including the one that could open the files. Giving a judge access to the evidence is not the same as it using the evidence.

One intervention clearly worked: a fixed checklist rubric cut cross-family judge disagreement from 34.2 points to 13.2. Model family drove verdicts more than rubric did (34.2 across families against 14.5 within one).

How it was built

A generator writes a tree of notes and records the answers as it writes them, so scoring is set overlap against known truth rather than a model’s opinion. Two corpora: 60 files (~50k tokens) and 400 files (~316k tokens, past the worker’s window).

Two design choices carry the validity. Planted lines are scattered through filler, so one search hit does not hand over everything nearby. And the semantic task’s criteria are written as six paraphrases each, combined pairwise — no single pattern match answers it, and an agent cannot know the paraphrase set in advance. Without that, the “semantic” task collapses into a search task and every configuration scores the same.

Three things checked rather than assumed

  • The ground truth was re-derived from disk. When five runs returned the same wrong total, the benchmark was the first suspect. It was correct; the agents were consistently making the same mistake.
  • The scheduling simulation was rewritten after reporting pipelining as 0.63× — worse than a barrier. It had booked future worker slots nothing needed. Corrected, it shows pipelining helps only when the pool is not the bottleneck (1.07–1.14×).
  • Harness failures were separated from model failures by their stored stdout, and two cells were re-run. Scoring a flaky call as zero would have penalised whichever configuration happened to hit it.

What would change the answer

  • Most cells are n=3, over-window cells n=2–5. Cost differences of 4–35× survive that easily; accuracy differences of a few points do not, and are reported as inconclusive.
  • One small worker model throughout. A larger model would raise every baseline and shrink the headroom where verification helps.
  • Each call pays a fixed harness prompt, inflating fan-out cost against a bare API orchestrator. Directions hold; magnitudes are an upper bound.
  • Every task here was read-only, so the strongest structural claim in the literature — that writes should stay single-threaded — could not be tested and is not claimed.

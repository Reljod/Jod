## The three findings that matter

### 1. Nothing in the recall family can answer "what is true now"

Every strategy without a control plane scores **0.04–0.27** on current-value
questions. The best flat retriever manages 0.17. `versioned_factstore` scores
**0.73** on the same questions using the same channels.

The `stale_above` column explains it: superseded versions outrank the current
one **35–54%** of the time for flat retrievers. That is not a tuning failure —
an outdated fact is a *near-perfect* lexical and semantic match for a question
about the current one. Relevance ranking cannot distinguish "true" from "was
true", because the two are textually identical. Nothing you do to the ranker
fixes this; the fix has to live somewhere else.

This is P3, and it is the strongest result in the experiment.

### 2. Long context contains everything and governs nothing

`full_context` scores a perfect **1.00** on stable recall and **1.00** on
multi-hop — it holds every chunk, so of course it does. On the same run it
scores **0.00** on current-value, **0.00** on retraction, and **0.00** on
poisoning, with an attack success rate of **1.00**. It costs **314×** the tokens
of the winner and still ends up 0.25 composite behind it.

The failures are not recall failures. Contradictory versions are all present
and unordered; the retracted fact is present and unmarked; the attacker's chunk
is present and indistinguishable from the owner's. Long context solves
*availability* and does not touch *governance* — and governance is most of what
"memory" actually means once a corpus has a history.

Caveat, stated in [`HYPOTHESES.md`](HYPOTHESES.md) limitation 2: this scores the
evidence layer, so `full_context` gets no credit for an LLM resolving conflicts
itself. Real models do sometimes resolve recency — and arXiv:2606.01435 measures
that ability falling from 75% to 61% as context grows from 64K to 262K tokens.
The direction of this result is safe; the magnitude is generous to the memory
side.

### 3. Ranking and truth must be separate mechanisms

The two mechanisms compose cleanly because they answer different questions:

| | answers | mechanism | measured effect |
|---|---|---|---|
| Control plane | what is *true* | deterministic supersede / retract / trust | current 0.17 → 0.73 |
| Recall plane | what is *relevant* | hybrid ranking over what survived | unchanged |
| Second hop | what is *connected* | pseudo-relevance feedback into reserved slots | multihop 0.00 → 0.42 |

Neither half works alone. `graph_expansion` (hop, no control plane) manages
multi-hop 0.58 but current-value 0.12 → composite 0.328.
`versioned_factstore` (control plane, no hop) gets current-value 0.73 but
multi-hop 0.00 → 0.598. Together: 0.675, with no axis regressing.

The one design rule that made the combination work is in the code comment on
`second_hop`: **give the second hop reserved extra slots, never let it displace
round one.** The first implementation merged the two rounds and bought multi-hop
0.00→0.67 at the cost of current-value 0.73→0.48 — a net composite *loss*.
Same mechanism, same parameters; only the merge policy differed.

## Two bugs found in shipped defaults

Both are properties of OpenClaw's real code, reproduced faithfully here.

**The 0.7/0.3 fusion split is not a constant.** Swept on a held-out tuning seed,
the optimum is **0.2** — 0.337 composite versus 0.260 at 0.7, a 30% relative
loss. The right weight tracks how good your embedder is relative to your lexical
channel. With a strong neural embedder the optimum plausibly moves back toward
0.7; the point is that it is a *tuned* value being shipped as a default, and
nothing in the system tells you when it stops fitting.

**`minScore: 0.35` is coupled to the fusion formula's scale.** It is an absolute
threshold compared against a score whose range depends on both the embedder's
cosine distribution and the fusion arithmetic. Measured:

| fusion | floor 0.00 | floor 0.35 |
|---|---|---|
| linear, vw 0.7 (shipped) | 8.0 results | 7.7 results |
| linear, vw 0.2 (tuned) | 8.0 results | 3.2 results |
| RRF, vw 0.2 | 8.0 results | **0.0 results** |

Under RRF, scores are `1/(60+rank)` ≈ 0.016 at best, so any floor above 0.1
silently returns nothing. Changing the fusion formula — a reasonable-looking
refactor — would disable retrieval entirely with no error raised. A relative
floor (a fraction of the top score) has none of this coupling.

## What I would build

Ranked by measured value per unit of complexity:

1. **A deterministic control plane.** Versioned facts with validity intervals,
   real deletion, write-time trust admission. Biggest single effect in the
   experiment (+0.34 composite over the best flat retriever) and the cheapest
   thing in the table at 68 tokens/query. Conflict resolution is `max(version)`
   in plain code — never a prompt.
2. **A second retrieval hop into reserved slots.** +0.42 on multi-hop for ~14
   extra tokens. Reserved slots, not merged results.
3. **Hybrid recall over the survivors** — but sweep your own weights, and use a
   relative score floor.
4. **Skip the earned-promotion tier.** Zero measured gain, +62% tokens. It may
   pay off under a skewed, repeating query distribution; it did not here, and
   that should be demonstrated before it is built.
5. **Skip temporal decay as a freshness mechanism.** It destroyed long-tail
   recall (0.40 → 0.00) to buy less current-value improvement than the control
   plane gives for free. OpenClaw ships it off by default; that looks correct.

## What this experiment cannot tell you

- **Absolute numbers are not comparable to LoCoMo or LongMemEval.** Different
  corpus, no LLM, evidence-layer scoring. Only the *ordering* transfers.
- **The dense channel is Random Indexing, not a neural embedder.** Findings
  about fusion weights (the sweep) are embedder-sensitive and would move with a
  real model. Findings about the control plane involve no embedding comparison
  and do not move.
- **Extraction cost is unmeasured.** The control-plane strategies assume a fact
  extractor. Here it is simulated at 90% recall / 5% false positives; in
  production it is an LLM call per ingested chunk, which is a real bill this
  experiment does not put a number on.
- **One synthetic corpus.** Adversarial structure is controlled precisely, at
  the cost of realistic phrasing and topic drift. Four seeds confirm the
  ordering is not a draw artefact; they do not confirm it generalises to human
  conversation.
